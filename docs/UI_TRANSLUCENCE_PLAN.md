## 0. 结论速览

建议4 的**方法论是对的，而且比多数"现代化"建议更克制**——它明确把玻璃限制在 chrome 层、明确禁止玻璃内容层、明确要求降级。这三条恰好和岑序已有的设计决策同向。

但它是一篇**通用阅读器随笔**，直接套到岑序上有三个问题：**排版建议对中文不适用**、**降级方案在项目真实目标设备上不成立**、**最关键的玻璃方案在当前外壳结构下根本不会产生效果**。

| 建议4 的主张 | 判定 | 一句话理由 |
|---|---|---|
| 玻璃仅用于 chrome 层，不用于内容 | ✅ 采纳 | 与现状完全兼容，阅读页工具栏已经这么做了 |
| 每个视图最多 2–3 处玻璃 | ✅ 采纳 | 写成规范硬约束 |
| 正文层绝不半透明 | ✅ 已是现状 | 写进规范做守门条款 |
| 表面层级代替阴影戏法 | ✅ 已是现状 | 面板化外壳已是这个思路，本轮不重复做 |
| 留白代替边框分隔 | ⚠️ 部分采纳 | 卡片层已做，顶栏/侧栏的 1px 描边仍是大头 |
| 背景光晕代替纯色平铺 | ✅ 采纳，最高性价比 | 零结构改动，但必须限定作用范围 |
| 排版是最高级的通透 | ⚠️ 采纳但要改写 | 建议4 的"正文无衬线"对中文是错的，见 §2.1 |
| `prefers-reduced-transparency` 降级 | ⚠️ 采纳但不充分 | 项目目标设备上它可能根本不生效，见 §2.2 |
| 不支持 backdrop-filter 时 fallback | ✅ 采纳 | 现状只覆盖了 color-mix 丢失，没覆盖"认 color-mix 但不认 backdrop-filter" |
| 玻璃用于顶栏、浮层面板 | ⚠️ 需前置条件 | 当前外壳结构下 blur 一片纯色，见 §2.3 |

## 1. 建议4 已经与岑序同向的三件事

这三条不需要改任何东西，写进规范即可。

**① 内容层与 chrome 层的分离已经是现状。**
`--c-bg-reader` 在四个阅读主题（light / dark / sepia / oled）下全是**不透明纯色**，正文容器从不参与半透明。这正是建议4 第 7–10 行那条"Apple 核心法则"。

**② chrome 层的玻璃已经存在。**
`reader.css:142-157` 的 `.reader-topbar / .reader-bottombar` 已经是 `color-mix(surface 80%, transparent)` + `backdrop-filter: blur(12px)`，并且注释里已经写明了降级意图（"旧 WebView2 会丢掉 color-mix，退成不透明底色（半透明毛玻璃是加分项，不是必需）"）。**建议4 的教科书场景，岑序已经实现了。**

**③ 表面层级代替厚重阴影，已经是 v1.4 的主线。**
面板化外壳（窗口 → 面板 → 卡片三层，用色调差而非投影分层）、卡片"近距阴影负责抬起 + 极淡描边负责切边"的两段式阴影，都是建议4 第 38 行那条原则的落地。

> **建议4 真正缺的不是"要不要通透"，而是"通透到哪一层、什么时候才成立"。**

## 2. 三处必须修正

### 2.1 排版建议把中文搞反了

建议4 第 62 行：

> 标题使用过渡衬线字体唤起书卷气，正文使用人文主义无衬线字体确保屏幕可读性。

岑序现状是**对的**，建议4 的方向在这里**不适用**：

| 层 | 岑序现状 | 建议4 想要的 | 判断 |
|---|---|---|---|
| 阅读正文 | `--font-reader` = 思源宋体 / Noto Serif CJK | 人文主义无衬线 | **不要改** |
| 界面 chrome | `--font-ui` = 系统黑体栈 | （未提） | 现状合理 |

三点理由：

1. **"人文主义无衬线"是拉丁排版概念**，Verdana / Tahoma 一路的东西。中文没有这个字体类别，把思源宋体换成黑体只会得到更硬的中文。
2. **中文长文阅读，宋体是更优解**。黑体（PingFang / 微软雅黑）在 18px 下的字面率高、笔画均匀度差，长时间阅读疲劳明显高于宋体；思源宋体的横细竖粗与字面率变化在小字号下反而更利于辨识。岑序阅读页正文 18px / 行高 1.75 的配置是对的。
3. **建议4 的"标题用衬线"在岑序对应的是应用内标题**（书名、章节名），不是正文。书名当前是 `--font-ui` 黑体 14px——但把它改成衬线在书架层收益极小（一行 14px 的中文标题，衬线带来的"书卷气"几乎读不出来），真正值得做衬线的是**阅读页的章节标题**。

**改写后的版本**：
> 正文保持衬线（中文长文阅读的最优解）；标题若需"书卷气"，用**字重与字距**而不是换字体家族来实现。

**这同时回答了审查报告里的 E1**：与其给全局 UI 换字体（安装包膨胀），不如把"字体性格"投资在两个签名位——**阅读页的章节标题**（衬线 + 大字距）和**品牌字「岑序」**。

### 2.2 降级方案在项目真实目标设备上不成立

建议4 第 52–56 行把降级拆成两件事：① 不支持 `backdrop-filter` → 接近不透明的 fallback；② `prefers-reduced-transparency: reduce` → 回退到不透明。

**方向对，但把②当成了主降级路径，而它在本项目的目标设备上可能完全不存在。**

实测与官方数据（Chrome 118 起提供 `prefers-reduced-transparency`）：

| 目标环境 | `backdrop-filter` | `prefers-reduced-transparency` |
|---|---|---|
| 桌面 WebView2 **109**（本项目用户机器的版本，`vite.config.ts` 写明） | ✅ Chromium 76+ | ❌ 需 118+ |
| 桌面 WebView2 118+ | ✅ | ✅ |
| Android WebView 118+ | ✅ | ✅ |
| Android WebView 旧版 | ✅ | ❌ |
| **iOS WebView（Safari 内核）** | ✅ | ❌ **永久不支持** |
| Firefox | ✅ | ❌ |

两个直接后果：

1. **在用户自己的那台机器上，`prefers-reduced-transparency` 这条降级根本不会触发**（WebView2 109 < 118）。仅靠它，等于没有降级。
2. **iOS WebView 永远不会有该偏好**，但它有 `backdrop-filter`。

**结论：降级的主路径必须换成能力检测，而不是偏好检测。**

```css
/* 主路径：设备根本没有模糊能力 → 直接实心 */
.glass {
  background: var(--glass-bg-fallback);              /* 实心兜底，永远写在第一行 */
  background: var(--glass-bg);                       /* 支持 color-mix 才生效 */
  backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));
}

@supports not (backdrop-filter: blur(1px)) {
  .glass {
    background: var(--glass-bg-fallback);
    backdrop-filter: none;
  }
}

/* 增强路径：用户主动开了系统「减少透明度」→ 再退回实心 */
@media (prefers-reduced-transparency: reduce) {
  .glass {
    background: var(--glass-bg-fallback);
    backdrop-filter: none;
  }
}
```

> 现有 `reader.css:152-153` 的 `background: var(--c-bg-surface); background: color-mix(...)` 写法是对的（老 WebView 丢 color-mix 就退成实心），但它只覆盖了"不认 color-mix"。**"认 color-mix 但不认 backdrop-filter"这个组合目前是裸奔的**，必须补 `@supports not` 兜住。

还有一条建议4 没说清、但必须写死的规则：**没有模糊时，fallback 的不透明度必须接近 1**。
原因不是对比度，而是**没有模糊就没有"透"的语义**——0.7 的白板后面若透出清晰的卡片标题，两层文字会直接打架。所以 fallback 的 alpha 下限建议 **≥ 0.94**（亮色）/ **≥ 0.96**（暗色），而不是建议4 说的模糊的"接近不透明"。

### 2.3 玻璃在当前外壳结构下不会产生效果（最关键）

建议4 反复强调的场景是"当用户滚动正文时，导航栏的玻璃效果是否让文字可读地透过来"。

**这句话在岑序的书架层现在不成立。** 原因在 v1.4 的面板化外壳（`components.css:3411` 起）：

```
.app-shell  padding: 8px; gap: 8px;  background: --c-bg-app      ← 纯色
  ├─ .topbar     background: --c-bg-surface (纯白)  ← 独立不透明面板
  ├─ .sidebar    → .side-panel × 3，background: --c-bg-surface (纯白)
  └─ .content    background: --c-bg-app (纯灰)
```

顶栏的模糊采样区域（它的正后方）是 `--c-bg-app` 的一块**纯色**，中间还隔着 8px 的沟槽。

→ 给顶栏加 `backdrop-filter: blur(12px)` 的实际效果是：**blur 了一片纯色，什么也透不出来**。视觉上只是把一块不透明白板换成半透明白板 + 一道 1px 描边 + 一圈阴影——**比现在更脏**，像多贴了一块没压平的塑料片。

侧栏的 3 块面板同理，背后也是纯色。

**所以：建议4 把顺序倒过来了。**

```
拍平（外壳去盒子）  ──►  玻璃才有东西可透  ──►  通透感成立
     ↑
  这是前提，不是选项
```

而"拍平"恰好就是建议4 自己第 38 行主张的"用表面层级代替厚重分割"、也是 `UI_REVIEW` 里 P0-1（卡片去框）+ P1-5（侧栏三盒合并）的方向。**建议4 和审查报告在终点汇合，但建议4 把它当成了前提而不是成果。**

建议4 说"每个视图最多 2–3 个焦点元素"。落到岑序的每个视图：

| 位置 | 用玻璃 | 理由 |

| 书籍右键菜单 `.book-menu` | ✅ 建议新增 | 小浮层，模糊能强化"浮在卡片上"的层次 |

| 对话框 `.dialog` / `.private-shelf` | ⚠️ 可选 | 对话框需要强聚焦，建议保留实心 + 更强阴影；私密书架同理 |
| **书架顶栏** | ✅ **v1.7 已用（有条件）** | 拍平之后才成立（§2.3）。条件：顶栏浮在滚动内容之上、且只在滚到它下面时才淡入；静止时仍完全透明 |

**每个视图的玻璃数量**：书架 0 处（拍平后 ≤2）、阅读页 3 处（顶栏 / 底栏 / 目录）——**正好落在建议4 的 2–3 处上限内**。

## 4. Token 方案

写进 `tokens.css`（结构层）与 `themes.css`（双主题值）。

### 4.1 结构 token（tokens.css）

```css
--glass-blur: 12px;
--glass-saturate: 1.25;
--glass-radius: var(--r-lg);
```

### 4.2 主题值（themes.css）

```css
/* 亮色：白玻璃压在浅灰底上，描边几乎不可见，边缘靠 blur 自身产生的亮边 */
[data-theme="light"] {
  --glass-bg: rgba(255, 255, 255, 0.72);
  --glass-bg-fallback: rgba(255, 255, 255, 0.96);
  --glass-border: rgba(255, 255, 255, 0.55);
  --glass-shadow: 0 8px 24px rgba(16, 24, 40, 0.10);
}

/* 暗色：描边改为提亮（暗底上压暗等于消失），saturate 补回被背景压掉的彩度 */
[data-theme="dark"] {
  --glass-bg: rgba(30, 33, 38, 0.72);
  --glass-bg-fallback: rgba(30, 33, 38, 0.96);
  --glass-border: rgba(255, 255, 255, 0.10);
  --glass-shadow: 0 8px 24px rgba(0, 0, 0, 0.44);
}
```

> 建议4 只给了亮色的 `rgba(255,255,255,0.7)`。**暗色主题必须另配**：暗底上白色描边是唯一的边缘定义，压暗描边等于没有描边。

### 4.3 组件类

```css
.glass {
  background: var(--glass-bg-fallback);
  background: var(--glass-bg);
  border: 1px solid var(--glass-border);
  border-radius: var(--glass-radius);
  box-shadow: var(--glass-shadow);
  backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));
}

@supports not (backdrop-filter: blur(1px)) {
  .glass {
    background: var(--glass-bg-fallback);
    backdrop-filter: none;
  }
}

@media (prefers-reduced-transparency: reduce) {
  .glass {
    background: var(--glass-bg-fallback);
    backdrop-filter: none;
  }
}
```

## 5. 背景光晕（最高性价比的一步）

建议4 第 58–59 行。做，但要把作用范围钉死，否则会毁掉卡片。

**三个约束**：

1. **只放在内容区背景（`.content`），不放 `body` / `.app-shell`**。放 app-shell 的话，光晕会漫到顶栏与侧栏底下，整页都"发灰"。
2. **绝对不进阅读正文层**。`--c-bg-reader` 必须保持纯色——纸面感来自纯色，渐变会让正文像浮在彩色板上。
3. **卡片不透明，所以网格区的光晕只从卡片之间的缝隙透出**，不会给卡片本身染色。这是把光晕放在 `.content` 而不是 `body` 的关键收益。

```css
/* 亮色：底本来就浅，幅度必须比暗色更小，否则一眼看出是"打了层滤镜" */
.content {
  background:
    radial-gradient(1100px 560px at 10% -6%,
      rgba(47, 111, 235, 0.075), transparent 62%),
    radial-gradient(880px 480px at 94% 106%,
      rgba(91, 141, 239, 0.065), transparent 62%),
    var(--c-bg-app);
}

/* 暗色：底近黑，同样 alpha 的蓝会显得更强，两处都下调 */
[data-theme="dark"] .content {
  background:
    radial-gradient(1100px 560px at 10% -6%,
      rgba(91, 141, 239, 0.055), transparent 62%),
    radial-gradient(880px 480px at 94% 106%,
      rgba(47, 111, 235, 0.045), transparent 62%),
    var(--c-bg-app);
}
```

**调参方法**：起步值给在上面，然后实机调到"**看得见但说不出哪里变了**"为止。建议4 说"几乎不可察觉"是对的——光晕的价值在于消除"毛坯感"，一旦能被指认为"有个光斑"，就变成了新的视觉噪音。

**验收**：截图对比时把两张图并排放大到 200%，若第一眼能指出光晕在哪，幅度减半。

## 6. 性能与降级（建议4 未覆盖）

`backdrop-filter` 作用在**滚动区域**时，浏览器每帧都要重新采样并合成。岑序的阅读页是滚动正文 + 自动隐藏工具栏 + 翻页动画三者叠加。

| 风险 | 表现 | 处理 |
|---|---|---|
| Android 低端机滚动掉帧 | 正文滚动发涩 | 工具栏 blur 从 12px 降到 8px；或工具栏只在滚动停止 120ms 后启用 blur，滚动中换成半透明纯色（`transition` 切换） |
| 翻页动画期间合成开销翻倍 | 翻页掉帧 | 翻页动画期间临时关 blur（用 `data-flipping` 属性切到 `--glass-bg-fallback`） |
| 菜单/Toast 短暂出现 | 一次性合成开销，可接受 | 不处理 |

> **注意不要把性能降级和 `prefers-reduced-transparency` 混用**。前者是"设备扛不住"，后者是"用户不想要"。这是两个独立维度，混用会让"用户主动要求不透明"的意图被性能逻辑覆盖。建议4 没有区分这一点。

## 7. 与现行规范（UI_SPEC v1.5）的冲突：需要裁决

`UI_SPEC.md` v1.5 刚刚把**"窗口 → 视图 → 卡片"三层结构**写死进规范。**建议4 的终点（玻璃浮层）会把三层降级为两层（内容 + 浮层）。**

三个可选裁决：

| 方案 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **A · 保持三层，书架层不做玻璃** | 顶栏与侧栏维持实心面板，只在**浮层**（目录 / 抽屉 / 菜单 / Toast）用玻璃 | 书架层没有通透感，视觉改善主要来自光晕 | ✅ **推荐**。结构稳定、风险最低、光晕已经能带来"告别毛坯"的感知 |
| **B · 拍平 + 顶栏玻璃** | `.app-shell` 去 padding/gap，`.content` 全高滚动，顶栏 `position:absolute` 浮在上面做玻璃 | 顶栏不再有"面板"存在感；滚动内容从顶栏下穿过；**需改写 UI_SPEC v1.5 的三层结构**；顶栏与状态栏安全区要重新处理 | ✅ **已于 v1.7 落地**（第四批）。原判断「需改写 v1.5 三层结构 + 重处理安全区」两项都命中 |
| **C · 折中：顶栏去框但保持实心** | 顶栏去掉 1px 描边与独立圆角，读作"内容区的页眉"而不是"浮在灰底上的白板" | 几乎零成本 | ✅ **推荐，可与 A 同期做**。这是"去掉盒子"里性价比最高的一条 |

**推荐路径：A + C 先做，B 留作后续专项。**（B 已于 2026-11-16 作为第四批落地，见下方更新）

> **`2026-11-16 更新`：B 已落地。** 顶栏改为 `position:absolute` 覆盖滚动内容，
> 玻璃以独立 token（`--glass-header-*`）挂在 `.topbar::before` 上，
> 由 `.app-shell[data-scrolled]` 在滚动时加强（静止 0.55 → 滚动 1）;
> **静止档在 v1.10 由「完全透明」上调**——真机上完全透明时用户读不出顶栏是浮层，

## 9. 一句话总结

建议4 讲对了"通透是层级不是透明"，也讲对了"玻璃只给 chrome、不给内容"；**但它默认了一个"内容在玻璃后面流动"的界面，而岑序现在是"面板各自独立"的界面**——所以它最有价值的两条（背景光晕、排版签名位）可以直接吃，最需要改造的一条（玻璃顶栏）必须等外壳拍平之后再做，而**降级路径得从偏好检测改成能力检测**，否则在 WebView2 109 和 iOS WebView 上等于没有降级。
