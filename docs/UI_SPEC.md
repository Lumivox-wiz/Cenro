阅读器 UI 设计规范 v1.13

版本：v1.13（液态玻璃材质：新增 data-material 维度，见 §3.5 与下方 v1.13 条目）
适用：Tauri 2 + React + TypeScript 桌面端
定位：本地优先、小说 / 漫画 / PDF 三格式统一的桌面阅读器
变更说明：
· v1.13 新增**表面材质**维度 `data-material="liquid"`，默认 flat 时不写该属性，与 v1.12 逐像素一致。液态玻璃是**主题之外的正交维度**（light + liquid / dark + liquid 都可组合），不是第三个 data-theme 值。落点只三处：顶栏（`::before` 模糊 + `::after` 棱边）、`.glass` 浮层（折射扫光）、卡片封面（棱边与冷/暖色散，**不加 backdrop-filter**）。卡片、纸面、正文一律不加玻璃——30 个封面 = 30 个离屏合成层，且封面本就不透明。棱边刻意独立于带 opacity 的 `::before`，否则静止态高光被一起衰减，玻璃退化成色带。全部液态变量覆盖包在 `@supports (backdrop-filter)` 内，`--glass-bg-fallback` 不动。
· v1.11 把所有圆角从 `border-radius` 的圆弧换成**连续曲率**（`corner-shape: squircle`）：直边与圆角相接处曲率不再突变，过渡更顺。半径同步补偿（6→8 / 8→11 / 13→16 / 9→13 / 16→20），**补偿只在支持该特性时生效**，不支持的环境仍拿到基准值 + 普通圆角，与 v1.10 逐像素一致。真圆元素（空状态圆底、PIN 圆点、滑块拇指）显式改回 `round`。
· v1.10 修正一处真机反馈：顶栏玻璃原本**静止时完全透明**，只有滚动才淡入。真机上这个判断不成立——静止态顶栏与内容同为一片纸色，用户读不出这里有一层浮起来的栏，会直接判成「方案 B 没做」；有了背景图之后，顶栏控件还会糊在图上没有依托。改为**静止 0.55、滚动升到 1**。0.55 在纯纸面上只是一条极淡的分界，不构成 v1.6 批判过的「白板」。
· v1.9 给书架加了两件"用户自带素材"的能力：① **自定义背景图**，可调填充方式 / 不透明度 / 模糊半径 / 纸色遮罩，只作用于书架层，阅读页纸面仍为纯色；② **莫奈取色**，从背景图取一个主色相派生成配色，**只接管强调色一族与内容区光晕**（`--c-accent*` / `--c-bg-selected` / `--glow-*`），纸面、文字、卡片颜色一律不动。③ 强调色与文字版强调色按当前主题**各自实算对比度**（图形 3:1 / 文字 4.5:1），同一张图在亮暗下得到不同色值，这是设计而非 bug。④ 背景图开启时**玻璃浮层退成实色**：抽屉里全是 12~13px 的小字，背后换成照片后玻璃会整体发虚。
· v1.8 只修「窄窗里丢信息」这一类问题，不动视觉方向：① 列表视图在 <768px 退化为两列时，进度不再跟着消失，百分比挂到书名行末尾；② 侧栏折叠态不再隐藏计数，改为「图标在上、数量在下」纵向堆叠（条目 40 → 46px）；③ 窄屏「导入」降级为图标按钮，把约 30px 还给搜索框；④ 搜索占位符按可用宽度而非 UA 切换。附带修掉一处既存 bug：窄窗收「类别」列的媒体查询没有下界，把手机上的两列定义整条盖掉，列表视图在手机上一直只显示封面。
· v1.7 把顶栏从排版里摘出去，**内容从顶栏下面滚过**（原 UI_TRANSLUCENCE_PLAN.md 的「方案 B」）：① `.topbar` 改为 `position:absolute` 覆盖滚动内容，侧栏与内容区各自补 `padding-top` 让位；② 顶栏玻璃分两档——静止 0.55、内容滚到它下面时升到 1，由 `.app-shell[data-scrolled]` 触发（静止档 v1.10 由「完全透明」上调，理由见 §2.9.1）；③ 顶栏玻璃是**独立 token**（`--glass-header-*`），不复用浮层那套：背后是任意封面而非静态文字，alpha 与 blur 都要另算；④ 玻璃挂在 `.topbar::before` 而非 `.topbar` 本身——`backdrop-filter` 会成为 `position:fixed` 子元素的包含块，挂在顶栏上会把 MenuShell 菜单关进 56px 盒子里裁掉。
· v1.6 把表面层级从「三层盒子」改为「一张纸 + 物 + 浮层」：① 外壳去掉 8px 留白与各面板的独立底色 / 描边，顶栏读作页眉、侧栏读作页边目录；② 书架卡片去掉白底 / 描边 / 内边距，**封面成为卡片唯一的实体**，阴影体系从 `--shadow-card` 换成 `--shadow-cover`；③ 新增 `--glass-*` 与 `.glass` 材质，只用于浮层（目录 / 设置抽屉 / 书籍菜单 / Toast），并以能力检测（`@supports not (backdrop-filter)`）为主降级路径；④ 内容区允许一层几乎不可察觉的背景光晕，阅读正文仍为纯色；⑤ 卡片悬停 CTA 由实心强调色改幽灵按钮，强调色实心块只剩「导入」。

0. 文档定位与优先级

本规范约束 P1 的全部界面实现。设计 token 一旦写入 src/styles/tokens.css，组件不得硬编码颜色、字号、间距。

优先级从高到低：

1. 本规范的「禁止事项」与「AI 设计执行约束」（第 12 章）
2. 设计原则（第 1 章）
3. Design Token（第 2 章）
4. 组件与交互规范（第 4–7 章）
5. 验收清单（第 13 章）

当实现与规范冲突时，优先保持设计系统一致性，并在 PR 描述中明确指出冲突点，不得静默偏离。

原则：书架层可以丰富，阅读层必须克制。 阅读界面的一切装饰都在和正文抢注意力。

---

1. 设计原则

1. 阅读优先：任何 UI 元素的存在都必须回答“它是否帮助阅读”。阅读页默认只有正文，工具栏按需出现。
2. 格式统一、交互自适应：书架、进度、设置视觉一致；翻页手势和布局按格式变化，但用户不需要学习三套界面。
3. 暗色优先：先设计暗色，再推导亮色。阅读器夜间使用是主场景。
4. 键盘是一等公民：所有高频操作（翻页、搜索、切换视图、退出沉浸）都有快捷键，且可在设置中查看。自动隐藏的工具栏必须有键盘等价物。
5. 本地即时感：不用 loading 转圈掩盖慢操作，用骨架屏、渐进加载和乐观更新。

2.2 排版

字体栈

```css

           "Noto Sans CJK SC", sans-serif;
```

| Token | 值 | 用途 |
|---|---|---|
| `--r-sm` | 6px | 输入框、标签、小按钮 |
| `--r-btn` | 8px | 按钮、导航项、侧栏选中块 |
| `--r-md` | 8px | 卡片、面板 |
| `--r-lg` | 13px | 书籍卡片、菜单 |
| `--r-cover` | 9px | 书籍封面 |
| `--r-xl` | 16px | 抽屉、对话框 |
| `--r-full` | 999px | 胶囊、圆点 |

**连续曲率（v1.11）**

v1.11 起统一用 `corner-shape: squircle`，把圆弧换成 superellipse 曲线——
直边与圆角相接那一点，曲率不再从 0 直接跳到 1/R，过渡是连续的。

· 依赖 Chromium 139+ 的 `corner-shape`。WebView2 157 实测可用；不支持的环境整块规则被
  `@supports` 丢弃，退化为普通圆角。
· **半径必须补偿**：同样的数值下，squircle 的视觉圆角比圆弧缩水 **35~40%**（曲线更贴直角）。
  不补的话所有控件都会读起来比原来「方硬」，封面尤其像被切了一刀。
  补偿值写在 `global.css` 的 `@supports` 块里（`8 / 11 / 11 / 16 / 13 / 20`），
  **只在该特性可用时生效**——这是刻意的：如果直接改 `tokens.css` 的基准值，
  不支持的环境会拿到「大半径 + 普通圆角」，比 v1.10 更圆，属于无谓偏差。
· **真圆要排除**：`.empty-icon`（64px 圆形底）、`.pin-dot`、滑块拇指、滚动条拇指
  显式设回 `corner-shape: round`。超椭圆会把正圆变成略方的形状，尺寸一大就看得出来。
· 形状特征：`squircle` = `superellipse(2)`，比圆更贴直角。半径 ≤10px 几乎看不出差别，
  16~20px 的抽屉与对话框能看出「更方但更顺」——这是特性，不是缺陷。
  再往上（`superellipse(3+)`）会明显变成切角，不用。
· 性能：书架滚动 90 帧实测，开启前后平均帧耗时 3.44ms vs 3.38ms（+1.8%），可忽略。

2.5 阴影

仅用于悬浮层与「物」，阅读区禁止常驻阴影。

```css
/* 暗色 */
--shadow-popover: 0 8px 24px rgba(0,0,0,0.32);
--shadow-dialog:  0 16px 48px rgba(0,0,0,0.48);
/* 亮色 */
--shadow-popover: 0 8px 24px rgba(0,0,0,0.12);
--shadow-dialog:  0 16px 48px rgba(0,0,0,0.18);
```

亮色阴影强度不足以单独区分层级，必须与 1px --c-border-subtle 描边组合使用（见 2.1）。

封面阴影（v1.6）：卡片去框后，封面是书架上唯一的「物」，阴影要自己把层次撑起来。

```css
/* 暗色 */
--shadow-cover:       0 1px 3px rgba(0,0,0,0.40), 0 10px 20px -14px rgba(0,0,0,0.75);
--shadow-cover-hover: 0 4px 10px rgba(0,0,0,0.45), 0 18px 32px -16px rgba(0,0,0,0.85);
/* 亮色 */
--shadow-cover:       0 1px 2px rgba(0,0,0,0.10), 0 10px 22px -14px rgba(0,0,0,0.38);
--shadow-cover-hover: 0 2px 6px rgba(0,0,0,0.10), 0 16px 28px -16px rgba(0,0,0,0.36);
```

· `--shadow-card` 已随卡片去框删除；卡片不再有底色，阴影只作用在封面上。
· 封面另有一条内描边 `inset 0 0 0 1px var(--c-cover-ring)`：纸色封面对浅灰底只有约 1.09:1，
  没有它 PDF / 文档类的浅封面在亮色下会失去边界。

侧栏选中块阴影（v1.7）：选中态从「平涂一层蓝」变成「一枚贴在纸上的薄片」。

```css
/* 暗色 */
--shadow-chip: 0 1px 3px rgba(0,0,0,0.55), 0 10px 22px -10px rgba(0,0,0,0.85),
               inset 0 1px 0 rgba(255,255,255,0.08);
--shadow-chip-hover: 0 1px 2px rgba(0,0,0,0.35);
/* 亮色 */
--shadow-chip: 0 1px 3px rgba(16,24,40,0.12), 0 10px 22px -10px rgba(16,24,40,0.45),
               inset 0 1px 0 rgba(255,255,255,0.9);
--shadow-chip-hover: 0 1px 2px rgba(16,24,40,0.06);
```

· 为什么需要：v1.6 拆掉侧栏面板后，选中态只剩 10~15% 的蓝底，在灰纸面上读作
  「这一格被涂了一笔」，而不是「你正在这一格」。贴纸投影 + 顶部内高光让它离开纸面约 1mm。
· 强度分两档：选中给整张贴纸，悬停只给一半（`--shadow-chip-hover`）。
  悬停若与选中同强，15 个条目里同时出现两块「浮起来」的，等于没有当前位置。
· 仍是「纸上的标记」而不是按钮：不做位移、不做描边、不加玻璃。

2.9 玻璃材质（v1.6）

玻璃只用于**浮层**：目录、设置抽屉、书籍菜单、Toast。
常驻结构（侧栏、卡片）与阅读正文一律禁用——玻璃的语义是「浮在内容之上」，
背后若是纯色，blur 只会得到一块没压平的塑料片（推导见 docs/UI_TRANSLUCENCE_PLAN.md §2.3）。

**唯一例外是顶栏**（v1.7，见 §2.9.1）：它在 v1.7 里脱离了排版、浮在滚动内容之上，
背后真的有东西在动，才第一次满足「浮在内容之上」这个前提。侧栏与卡片仍不适用——
它们背后永远是同一片纸色。

```css
--glass-blur: 12px;
--glass-saturate: 1.25;
/* 暗色 */
--glass-bg: rgba(34,37,44,0.72);   --glass-bg-fallback: rgba(34,37,44,0.97);
--glass-border: rgba(255,255,255,0.10); --glass-shadow: 0 8px 24px rgba(0,0,0,0.44);
/* 亮色 */
--glass-bg: rgba(255,255,255,0.72); --glass-bg-fallback: rgba(255,255,255,0.97);
--glass-border: rgba(255,255,255,0.55); --glass-shadow: 0 8px 24px rgba(0,0,0,0.10);
```

· 组件写法固定为：先写 `--glass-bg-fallback`，再写 `--glass-bg`，最后 `backdrop-filter`。
  老内核丢掉后一条声明时才有实心兜底。
· fallback 的 alpha 必须 ≥0.94：没有模糊就没有「透」的语义，0.7 的白板会让背后文字与浮层文字打架。
· 降级**主路径是能力检测**，不是偏好检测：目标环境 WebView2 109 不认识
  `prefers-reduced-transparency`（需 118+），只靠偏好检测等于没有降级。
  `@supports not (backdrop-filter: blur(1px))` 兜底，`@media (prefers-reduced-transparency: reduce)` 作为增强。
· 暗色下描边必须是提亮（白 10%）：暗底上压暗描边等于没有边界。

2.9.1 顶栏玻璃（v1.7，唯一例外）

顶栏是**唯一**允许用玻璃的常驻结构，且成立有前提：v1.7 起顶栏绝对定位于滚动内容之上，
背后是真的有封面在移动，不是一片纯色。

```css
/* 暗色 */
--glass-header-bg: rgba(30,33,40,0.70);  --glass-header-fallback: rgba(30,33,40,0.97);
--glass-header-line: rgba(255,255,255,0.08); --glass-header-shadow: 0 10px 20px -16px rgba(0,0,0,0.85);
/* 亮色 */
--glass-header-bg: rgba(255,255,255,0.70); --glass-header-fallback: rgba(255,255,255,0.97);
--glass-header-line: rgba(16,24,40,0.07);  --glass-header-shadow: 0 10px 20px -18px rgba(16,24,40,0.45);
/* 结构 */
--glass-header-blur: 18px; --glass-header-saturate: 1.35;
```

· **静止就有，但很轻**（v1.10 修正）：`opacity: 0.55`，滚动升到 `1`，`--dur-base` 过渡。
  v1.7 原本设为静止完全透明，理由是「静止画面里凭空一条带子，等于把 v1.6 刚拆掉的白板装回去」。
  真机验证推翻了这个判断：静止态顶栏与内容同为一片纸色，**用户读不出这里有一层浮层**，
  直接判成「方案 B 没做」；有背景图时顶栏控件还会糊在图上没有依托。
  0.55 在纯纸面上只是一条极淡的分界（不构成「白板」），有图时才真正承担分离职责。
· **不复用 `--glass-*`**：浮层背后是静态文字（需要保住它自己的可读性，故 0.72 高不透）；
  顶栏背后是持续移动的封面，blur 要更大（18px，12px 会把封面上的字糊成"看得见但读不出"的灰带），
  alpha 反而可以低一档——它的控件各自有底色或描边兜底。
· **挂在 `::before` 上，不挂在 `.topbar` 上**：`backdrop-filter` 会让元素成为
  `position:fixed` 子元素的包含块；顶栏里的 MenuShell 菜单正是 `fixed`，
  一旦被关进 56px 的顶栏盒子，`max-width:767px` 段的 `overflow:hidden` 会把它整块裁掉。
· 降级与 `.glass` 同一套：`@supports not (backdrop-filter)` + `prefers-reduced-transparency`，
  退到 `--glass-header-fallback`（0.97）并去掉 blur。
· 对比度实测（v1.7）：最坏情况是纯白 PDF 封面从顶栏下经过（sRGB 合成，非线性空间）——
  暗色 0.70 合成得 ≈ #5D5D5F，`--c-text-primary` #E6E8EB 对它是 **5.3:1**，过 AA；
  亮色 0.70 白玻璃压深封面得 ≈ #B0B0B0，深色文字 **7:1** 以上。低于 0.66 才会掉到 4.5 以下，故下限写死 0.66。

2.10 莫奈取色（v1.9）

从背景图里取一个主色相，派生成强调色、选中底与光晕。规则只有一条，但要守住：
**只接管强调色一族，纸面与文字一律不动。**

· 接管范围固定为 8 个变量：`--c-accent` / `--c-accent-text` / `--c-accent-hover` /
  `--c-accent-subtle` / `--c-bg-selected` / `--c-border-focus` / `--glow-a` / `--glow-b`。
· 不接管的：`--c-bg-app` / `--c-bg-surface` / `--c-bg-elevated` / 全部 `--c-text-*`。
  这些是正文可读性的地基，跟着图走会把整套对比度一起带翻——一张偏黄的图会让
  `--c-text-secondary` 从 4.8:1 掉到 3:1，而且**每张图掉得都不一样**，无法预设兜底。
· 对比度**按主题各算一遍**：图形（进度条 / 竖条 / 图标）需 3:1，文字版强调色需 4.5:1。
  做法是从一个起点明度沿「亮色往暗、暗色往亮」的方向迭代，直到达标。
  所以同一色相在 `data-theme="light"` 与 `"dark"` 下得到的是两个不同的色值，这是刻意的。
· 饱和度要**提纯**：照片的加权平均饱和度通常只有 0.15~0.3，直接当强调色是一块洗不干净的脏色。
  派生时乘 1.55 并夹在 0.42~0.74：下限保证「看得出有颜色」，上限防止推到荧光。
· 光晕沿用 §2.9 之前定下的幅度（亮 0.075/0.065、暗 0.055/0.045）；
  原图整体很暗（明度 < 0.25）时再降 30%——暗纸面上叠深色光晕等于没画。
· **取色在后端做**（`src-tauri/src/monet.rs`）：WebView 里背景图走 asset 协议属于另一个 origin，
  画到 canvas 会被 taint，`getImageData` 直接抛 SecurityError。
· 有效像素占比（`coverage`）低于 **0.02** 视为「这张图没有色调」，开关自动关闭并提示，
  不给一套谁也不像的灰。色板缓存记 `source`，与当前图片路径不一致即视为过期。

3. 主题机制

3.1 双主题属性

· 应用主题：根节点 data-theme="light | dark"。
· 阅读主题：阅读区额外 data-reader-theme="light | dark | sepia | oled"。
· data-theme 只接受解析后的实际值（light / dark），不接受 system。

3.2 system 解析规则

· 设置项存用户意图（light | dark | system）。
· 运行时由 JS 监听 prefers-color-scheme，把 system 解析为 light 或 dark，写入 data-theme。
· 系统主题切换时，应用主题即时跟随；阅读主题仅在设置为「跟随应用」时同步变化，独立设置时不跟随。

3.3 继承关系表

应用主题 阅读主题设置 实际表现
暗色 跟随应用 暗色
亮色 跟随应用 亮色
暗色 护眼 Sepia
亮色 OLED 纯黑
系统（解析为暗） 跟随应用 暗色
系统（解析为亮） 跟随应用 亮色
系统（解析为暗） 护眼 Sepia（不随系统变化）

3.4 禁止事项

· 禁止在组件里写死颜色；所有颜色引用 var(--c-*)。
· 禁止在阅读正文区使用纯白 #FFFFFF 背景 + 纯黑 #000000 文字。
· 禁止用 --c-accent 直接写亮色正文/标签文字，必须用 --c-accent-text。

3.5 材质（v1.13）

· 应用材质：根节点 data-material="liquid"。**flat 时完全不写该属性**（不是写 flat）。
  没开液态的用户，CSS 里 `[data-material="liquid"]` 开头的规则一条都不会被匹配。
· **材质与主题是两个正交维度，不是第三个主题值。**
  data-theme 管「用什么颜色」，data-material 管「表面由什么构成」。
  液态玻璃既可以是亮玻璃（light + liquid）也可以是暗玻璃（dark + liquid）；
  若塞进 data-theme 当第三值，themes.css 里亮色那 70 行变量要整份复制一遍，
  而且再也组合不出「液态 + 暗色」——这是硬性架构约束，不是偏好。

| 主题 | 材质 | 表现 |
|---|---|---|
| 亮色 | flat | 白纸 + 实心浮层（默认，与 v1.12 逐像素一致） |
| 亮色 | liquid | 白玻璃 + 棱边高光 + 冷/暖色散 |
| 暗色 | flat | 暗纸 + 实心浮层 |
| 暗色 | liquid | 黑玻璃 + 棱边高光 |

· **玻璃只落在三处**，其余一律不加：
  1. 顶栏：`::before` 承担模糊与底色，`::after` **单独**画棱边；
  2. 浮层 `.glass`（目录 / 抽屉 / 书籍菜单 / Toast）：加一道折射扫光；
  3. 卡片封面：`::after` 画棱边与色散，**不加 backdrop-filter**。
· **卡片不加模糊**：书架 30 本书 = 30 个离屏合成层，WebView2 上直接掉帧；
  且封面本就不透明，模糊采不到任何东西。
· **纸面与正文不加玻璃**：`--c-bg-reader` 必须纯色，渐变会让正文像浮在彩板上。
· **棱边必须独立于带 opacity 的层**。顶栏 `::before` 静止 0.78 / 滚动 1，
  高光若写进它的 box-shadow 会跟着一起衰减，静止态只剩一条灰线、玻璃退化成色带。
· 液态的变量覆盖**全部包在 `@supports (backdrop-filter: blur(1px))` 内**：
  不支持模糊的内核若读到降了 alpha 的 --glass-bg，会「透明生效、模糊不生效」，
  背后文字直接和浮层文字打架。放进 @supports 后两个块互斥，不可能同时命中。
· `--glass-bg-fallback` 任何材质下都不动（alpha ≥0.94），它是降级路径的实心底。

4. 布局规范

4.1 窗口与断点

最小尺寸：960 × 600。书架内容区最大宽度 1440px，水平居中。

断点 窗口宽度 侧栏 书架列数 阅读正文宽度
紧凑 960–1199px 折叠为 64px 图标栏 4 列 min(reader-page-width, 窗口宽 − 2×48)
标准 1200–1439px 240px 5 列 同上
宽屏 1440–1919px 240px 6 列 同上
超宽 ≥1920px 240px 7 列，内容居中留白 同上

超宽屏由 v1.1 的 8 列修正为 7 列：7×160 + 6×16 + 2×48 = 1312px < 1440px，避免卡片最小宽度与最大内容宽度冲突（8 列需 1488px，超出上限）。

列数余量核对（v1.3 补充）：4 列 784px、5 列 960px、6 列 1136px、7 列 1312px。标准断点 1200px 时内容区恰为 1200 − 240 − 96 = 864px，5 列需 864px，零余量——这是设计预期，卡片在该点正好 160px，不得为消除紧张感私自减列。
书架卡片宽度随列数变化，不随窗口无限拉伸；阅读正文宽度始终由 --reader-page-width 控制。

4.2 书架页

```
┌─────────────────────────────────────────────┐
│ 页眉（浮层 56px，内容从它下面滚过）            │
│ ☰ | Logo | 搜索 |(≤1199)分类 | 排序 · 视图 · 导入 · 设置 │
└─────────────────────────────────────────────┘
│ 页边 │  内容区（灰底 + 极淡光晕）             │
│ 目录 │  网格 / 列表                          │
│ 240px│                                       │
└──────┴──────────────────────────────────────┘
   灰底从窗口顶端连续到底部，中间没有任何面板切口
```

· 外壳（v1.6）：**一张纸**。窗口不再有 8px 留白，顶栏、侧栏、内容区共用同一片 `--c-bg-app`。
  这是玻璃材质成立的前提：v1.4 的面板化外壳里，顶栏背后是一块纯色 + 8px 沟槽，
  给它加 `backdrop-filter` 只会 blur 一片纯色（见 docs/UI_TRANSLUCENCE_PLAN.md §2.3）。
  · 顶栏无底色、无描边、无圆角，读作**页眉**；页眉里的控件（搜索 / 分类 / 排序 / 视图切换）
    抬一档底色到 `--c-bg-surface`，否则与页眉同色消失。
  · 侧栏无底色、无描边，读作**页边目录**；导航项直接落在纸面上。
  · 内容区是唯一带装饰的背景：两层极淡径向光晕（亮色 0.075 / 0.065，暗色 0.055 / 0.045，
    半径 1100×560 与 880×480，分别锚在左上与右下）。幅度以「看得见但说不出哪里变了」为准，
    一旦能被指认为「有个光斑」，就减半。光晕**只挂在 `.content`**，不进 body / app-shell / 阅读正文。

· 顶栏浮层（v1.7，方案 B）：`.topbar` 从 flex 排版里摘出，`position:absolute; top/left/right:0; z-index:4`
  覆盖滚动内容，**不再占据 56px 高度**。于是：
  · 侧栏与内容区各自补 `padding-top`：侧栏 `--topbar-h + --safe-top + --sp-3`（68px），
    内容区 `--topbar-h + --safe-top + --sp-6`（80px）。两处都比拍平前多 0（数值与 v1.6 完全一致），
    只是从"顶栏占位"变成"自己让位"。
  · `.content` 的滚动范围因此是整窗高，卡片真的从顶栏下缘滑过——这是 v1.6 无法成立的画面。
  · 玻璃由 `.app-shell[data-scrolled="true"]` 触发（`scrollTop > 2`），静止时完全透明。
    滚动监听直接写 DOM 属性，不走 `setState`：滚动每帧重渲染整个书架不可接受。
    另挂 `ResizeObserver` 兜住"切分类后书变少、`scrollTop` 被夹回 0 但不发 scroll"的残留玻璃带。
  · `z-index: 4`：压在 `.import-progress`（3）与旧值 2 之上，但在 `--z-dropdown`（100）之下——
    顶栏是一层皮，不是浮窗，菜单 / 抽屉 / 对话框仍要能盖住它。

· 顶栏布局（v1.5 修订）：左起一组（☰ / Logo / 搜索）＋ 右端一组（排序 / 视图 / 导入 / 设置），
  中间由弹性空间撑开。搜索框**不再绝对居中**——窗口变宽时它会与品牌名断开成两座孤岛。
  · 不再单印「当前分类」：桌面看侧栏激活项，≤1199px 看顶栏分类下拉，同一件事不说两遍。
  · 分类下拉在 ≥1200px 隐藏（侧栏带标签时重复）；768–1199 侧栏收成图标栏、<768 侧栏隐藏，
    这两种宽度下它是唯一能读出「当前在看哪一类」的地方，必须显示。
  · 排序与分类同为「自绘按钮 + MenuShell 菜单」，宽度固定（104 / 112px），
    切换时不推动右侧操作区。禁止使用原生 `<select>`：Android 弹系统灰底列表，Windows 弹 Win32 下拉。
  · 二级控件（分类、排序、视图切换、搜索）统一 `--c-border-subtle` 描边；
    只有聚焦态（`--c-border-focus`）和唯一的实心主按钮「导入」（`--c-accent`）可以加深。
  · 视图切换的选中态是「浅蓝底 + 强调色图标」，不是实心强调色块——强调色的实心块只留给导入。
  · 窄屏（<768px）「导入」降级为 32×32 图标按钮（v1.8）：两个字要吃掉约 30px，而那段宽度
    应该还给搜索框；移动端另有空状态入口与拖拽层兜住这个操作。可访问名由 `aria-label` 承担。
  · 搜索占位符按**可用宽度**切换（<768px 为「搜索」），不按 UA（v1.8）：

· 侧栏（v1.6）：240px，**一整栏连续面**，不再分三块独立面板：
  · 视图组：全部 / 最近阅读（跨格式的切面，不参与五族计数）

  · 选中态（v1.7）：浅蓝底 + `--shadow-chip` + 顶部 1px 内高光，读作**一枚贴在纸上的薄片**；

    不允许和选中同样强——同一屏出现两块「浮起来」的，等于没有当前位置。
    它仍然是纸上的标记，不是按钮：不位移、不描边、不用玻璃。
  · 工具组：设置（钉在侧栏底部 `margin-top:auto`）
  · 折叠为 64px 图标栏时同上，只隐藏**标签**；计数不丢（v1.8），改为「图标在上、数量在下」
    纵向堆叠，条目 40 → 46px。先试过右上角角标：这一列全是 2px 描边的线性图标，
    没有干净的角可放，数字要么压住笔画、要么浮在图标外侧读作散点。

    面板去掉后白只剩「封面」一种载体，侧栏不再与内容争「谁是盒子」。

· 侧栏折叠：顶栏最左侧 ☰ 按钮，快捷键 Ctrl/Cmd + \，动画 --dur-base。折叠后显示 64px 图标栏（紧凑断点自动进入）。
· 顶栏高 56px（`--topbar-h`，移动端再叠加 `--safe-top`）。v1.7 起它是**浮层**：
  自身不随内容滚走（`position:absolute`），但也不再占据布局高度，内容从它下面滚过。
· 网格视图（v1.4）：`auto-fill` + `minmax(176px, 1fr)`，列距 `--sp-5`、行距 `--sp-6`，

  列表视图封面 40×60（同为 2:3）。
· 列表视图（v1.4）：行高 64px，**五列**——封面 40×60 / 标题 / 类型 / 进度 / 最近阅读。

  `.list-head > span:nth-child(3){display:none}` 一并删除——类别删掉后第 3 个 span 变成「类型」，
  留着这条会把类型列一起藏掉。
  未读的行不画进度轨道，只显示「未读」；`0%`（打开过但没进度）仍显示 `0%`。
· 卡片悬停显示“继续阅读”浮层，不改变卡片尺寸。

4.3 阅读页（沉浸式）

v1.3 修正：顶栏移除「书签」按钮。P1 不做书签（UX 规范 §2.3），P2 增加书签时插入到「目录」与「设置」之间。

工具栏显隐规则：

· 进入阅读页即默认隐藏顶/底栏。
· 唤出（满足任一）：
  · 鼠标移入顶部/底部热区
  · 按 F6 在顶栏与底栏间循环聚焦
  · Tab 首次聚焦到顶栏
· 隐藏（同时满足）：
  · 鼠标离开工具栏与热区
  · 无键盘焦点在工具栏内
  · 无抽屉/对话框打开
  · 无操作持续 3 秒
· 暂停自动隐藏（任一成立即暂停计时）：
  · 工具栏内元素获得键盘焦点
  · 鼠标停留在工具栏内
  · 目录或设置抽屉打开
  · 对话框打开
· 点击正文区中央 50% 切换工具栏显隐（与第 6 节翻页热区一致）。

· 阅读区背景 = --c-bg-reader，正文左右内边距不小于 --sp-12。

热区尺寸：热区固定高 48px。顶栏高 48px 时热区与栏等高；底栏高 40px 时热区下探 8px，便于触发。这是有意为之，不是 bug。

4.4 设置页

· 以右侧抽屉（宽 360px）呈现，不跳转页面，不中断阅读。
· 分组（v1.9）：阅读 / 主题 / **背景** / 书库 / 备份 / 隐私 / 快捷键 / 关于。
  「备份」「隐私」是 0.11–0.12 新增的入口，此前未登记，补在这里；
  「背景」是 v1.9 新增，紧跟在「主题」后面——两者都是“换外观”，分开摆会让用户找不到。
· 所有设置项即时生效，无“保存”按钮。
· **分组菜单摘要（v1.12）**：只写「当前值」，不写「这页里有什么」。

  · 阅读 `衬线 18px` / 主题 `浅色` / 背景 `未设置` / 书库 `N 个目录` / 关于 `vX.Y.Z`

· **恢复按钮（v1.12）**：页级按钮文案为「恢复本页默认」，分组标题旁为「恢复默认」。

4.4.1 关于页（v1.12）

· **没有标语**：hero 只有 logo + 名称 + 版本。不写品牌口号，不写英文 tagline，
  不写「应用不联网」「无账号 · 无上报」这类应用承诺——承诺不是设置项。
· 分组行只写标签 + 箭头，**不写内容预告**（「目录 · 缓存占用 · 封面重建」这类全删）：
  子页里都有，预告一遍等于同一事实存两份。
· 格式清单（小说 / 漫画 / 文档 三行）保留：它是数据表不是标语，用户判断
  「我的文件能不能导入」时要用它，删了是真实信息损失。
· 已知不一致（待裁决）：这三行的分组是「小说 / 漫画 / 文档」，
  与侧栏的「文本 / 电子书 / 文档 / 漫画 / PDF」不是同一套分类法。

4.5 书架背景图（v1.9）

图层顺序固定为四层，不能调换：

```
纸色底（.app-shell 自身 background）
  → 背景图（.shelf-bg，可调 opacity / blur / object-fit）
    → 纸色遮罩（.shelf-bg-layer::after，可在设置里关掉）
      → 内容（.shelf-body：顶栏 4 / 侧栏与内容区 1）
```

· **只作用于书架层**。阅读页与 `.app-shell` 平级而非它的子元素，
  所以正文永远读不到背景图——纸面必须纯色，这是 v1.6 就定下的底线。
· **遮罩取值**：亮色 `rgba(243,244,246,.74)`、暗色 `rgba(23,25,30,.64)`。
  这个数字是用「侧栏 tertiary 计数是否还读得出」试出来的，不是审美选择：
  低于 0.7 时，浅蓝底图会让 `--c-text-tertiary` 掉到 3:1 附近。
· **模糊必须靠 overflow 裁**：`blur()` 会把图片边缘晕成一圈半透明，露出下面的纸色变成白边。
  外层 `.shelf-bg-layer` 用 `overflow:hidden` 收紧，图片自身 `scale(1.06)`，
  可见区域就始终落在图内（40px 半径内 6% 足够）。
· **内容区让出底色**：`.content` 的 `background` 简写最后一项是 `var(--c-bg-app)`，
  它是遮住背景图的唯一原因。启用时只覆盖 `background-color: transparent`，
  两层 radial-gradient 光晕保留——光晕叠在图上、图叠在纸色上。
· **玻璃浮层退成实色**：`[data-shelf-bg] .glass { background: var(--c-bg-elevated) }`。
  抽屉里全是 12~13px 的设置项与提示，背后换成照片后 0.72 白玻璃 + 12px blur 会让它们整体发虚。
  **顶栏不在此列**——它只有图标和输入框，且本来就该透出滚过的封面（§2.9.1）。
  这个标记同时写在 `<html>` 上，因为抽屉 / 书籍菜单 / Toast 都挂在 `.app-shell` 之外。
· **`.shelf-body` 必须 `position:relative; z-index:1`**：背景层是 `position:absolute; z-index:0`，
  按绘制顺序，定位元素整体画在非定位的正常流内容之上。少了这一条，侧栏的图标与标签
  会被背景层盖住，只剩普通流里唯一带 `position:relative` 的选中项可见——
  表现是「侧栏只剩右对齐的计数」，很容易被误判成折叠态样式串了。
· 图片不可用（文件被移走 / 删除）时整层不渲染，并回落到纯纸色，不显示半透明空层。

5. 组件规范

5.1 通用状态矩阵

所有交互组件必须实现以下状态：

状态 视觉要求 动效
Default 基础 token —
Hover --c-bg-hover / 边框变化 --dur-fast
Active --c-bg-active / 轻微缩放 0.98 --dur-fast
Focus outline: 2px solid var(--c-border-focus); outline-offset: 2px 无
Disabled opacity: 0.4; cursor: not-allowed 无
Loading 内容区骨架屏；按钮内允许小型 spinner 循环
Error 边框 --c-danger + 错误文案 无

Loading 边界：内容区/页面级加载必须使用骨架屏；按钮级异步操作允许小型 spinner；后台任务用进度条或非阻塞 Toast；加载失败切换 Error 状态。三者不互斥，但禁止用整页转圈替代骨架屏。

焦点环不得移除。

5.2 按钮

类型 高度 内边距 圆角 用途
Primary 32px 0 var(--sp-3) --r-sm 每屏最多 1 个（口径见下）
Danger 32px 0 var(--sp-3) --r-sm 危险确认，不计入 Primary 配额
Secondary 32px 0 var(--sp-3) --r-sm 次要操作
Ghost 32px 0 var(--sp-2) --r-sm 工具栏、图标旁文字
Icon 32×32 — --r-sm 纯图标，必须有 aria-label

Primary 配额口径（v1.3 统一）：同一视口层级内最多 1 个 Primary。工具栏、对话框、抽屉、空状态各自独立计数；一个工具栏内同样最多 1 个。Danger 不计入。

强调色按钮文字：暗色 Primary 使用 --c-text-on-accent（#0B1220，5.8:1），亮色 Primary 使用 --c-text-on-accent（#FFFFFF，4.57:1），不得混用 --c-text-inverse 导致对比度不足。桌面鼠标场景 32px 足够；触摸设备降级为最小 44×44px（加大内边距，不放大视觉尺寸）。

内边距 v1.3 修正：v1.2 的 14px / 10px 不在 4px 网格上，统一为 --sp-3（12px）/ --sp-2（8px），仍保持 32px 高度下的舒适文字区。

5.3 输入框 / 搜索

· 高度 32px，圆角 --r-sm，边框 --c-border-strong，背景 --c-bg-surface。
· 聚焦：边框变 --c-border-focus，不加外发光。
· 书架搜索：Ctrl/Cmd + F 聚焦，必须 preventDefault()。
· 搜索框宽度 `clamp(220px, 26vw, 420px)`，在 ≥1024px 窗口内绝对居中。
· 阅读页 Ctrl/Cmd + F：P1 不提供全文搜索，返回书架并聚焦搜索框（行为见 UX 规范 §8.3）。
· 输入即搜（防抖 200ms），支持标题/作者，P2 接 FTS5。
· 清空按钮仅在非空时显示。

5.4 书架卡片

· 卡面（v1.6）：**无底色、无描边、无内边距**。卡片不是一张纸，**封面才是那件物**；
  页面底色是唯一背景，文字直接落在纸面上。
  · 悬停只抬起封面（`translateY(-2px)` + `--shadow-cover-hover`），文字区不动。
  · 焦点环仍由全局 `:focus-visible` 画在整张卡上，键盘用户能看出是哪一本。
  · 触发这一改动的事实：v0.15.2 给白卡补「1px 描边 + 三层阴影」，是因为白卡对 `#F3F4F6` 只有 1.10:1；
    但那只是在修补「卡片必须是一张白纸」这个前提。前提换掉后，白框套彩框的问题从根上消失，
    `--shadow-card` / `--c-card-ring` / `--c-bg-card` 一并删除。
· 结构（v1.5，v1.12 修订）：封面（2:3）→ 标题（最多 2 行）→ 格式标签 · 作者（一行）→ 进度。
  **v1.12 删掉元信息行里的「分类」**：与列表视图同因——分类由格式推导，卡片上写
  「EPUB · 沈砚 · 电子书」是把同一个输入说两遍，还占掉一行宽度。
  「格式标签 · 作者」两段保留：格式是识别文件类型的唯一可见信息，作者是内容属性；
  作者缺失时该段留空，元信息行退化成只剩格式标签。
· 标题（v1.5）：14px，最多 2 行，`-webkit-line-clamp: 2`，并预留两行高度（`min-height: 2.6em`），
  单行标题的卡片不被压矮、同一行卡片的元信息基线一致。完整标题仍走 Tooltip。
  13px 单行会把《某某某：一个关于……的笔记》这类中文长书名截掉后半句，而后半句往往才是信息。
· 卡片信息分四段，间距分三档（v1.5）：封面 → 文字 12px；标题 → 元信息 2px；元信息 → 进度 8px。
  四段等距 8px 会让它读作四行等权列表，而不是「一本书 + 它的两个注脚」。
· 格式标签（v1.5）在元信息行首，内联小标签（`--fs-11`，`--c-bg-active` 底，`--c-text-secondary` 字），
  **不再压封面左下角**：压在封面上时会盖住真实封面图，还要为可读性加半透明底 + `backdrop-filter`。
  分类名与格式名相同时（PDF / 图像集）只显示格式标签，不重复。
  （v1.6：底色从 `--c-bg-app` 改为 `--c-bg-active`——标签现在落在页面底色上，同色底等于没有标签。）
· 悬停浮层（v1.6）：`to top` 渐变，峰值 0.72、42% 处 0.34、72% 处透明，覆盖封面下缘约 45%。
  原峰值 0.88 在米色封面上是一条硬黑带。
  · 主操作是**幽灵按钮**（白 14% 底 + 白 42% 描边 + 白字，高 36px），不是实心强调色：
    实心强调色块全站只属于「导入」。也不用强调色描边——遮罩压在浅色封面上合成约 `#464646`，
    强调色在其上仅 2.7:1；白字在同一底色上 8.9:1，任何封面底色下都成立。
· 进度**不再叠在封面上**，改为文字区的「3px 轨道 + 百分比」一行，颜色 `--c-accent`。
  未读（pct 为 0 或无进度）不渲染轨道；读完（pct ≥ 99）轨道降为 `--c-border-strong`。
· 列表视图进度：同上，百分比与轨道同一行；未读只写「未读」，不画空轨道。
· 缺失封面：显示格式占位图（小说/漫画/PDF 三种图标 + 底色），不要灰色方块。
· 卡片异常态（与 10.2 对应）：
  · 文件已丢失：整卡 opacity 0.5 + 右上角「文件已丢失」角标，右键提供「重新定位」。
  · 待恢复（删除事务中断）：整卡 opacity 0.6 + 角标「待恢复」，右键提供「重新定位」「移除记录」。样式与「文件已丢失」区分：前者用 --c-warning，后者用 --c-text-tertiary。
· 右键菜单顺序固定：打开 / 在文件夹中显示 / 编辑信息 / 分隔线 / 从书架移除 / 删除本地文件。
  · 「从书架移除」与「删除本地文件」必须分组或加分隔线，不得无分隔相邻。
  · 「删除本地文件」必须是 Danger 项并二次确认。

5.5 阅读器工具栏

· 顶栏按钮顺序固定：返回 → 书名（可点击跳书架搜索）→ 弹性空间 → 目录 → 设置。
  · P1 无书签按钮；P2 插入位置为「目录」与「设置」之间。
· 底栏：进度条（可拖动）+ 当前/总页 + 缩放（仅 PDF/漫画）+ 单双页切换（仅漫画/PDF）。
· 进度条拖动时显示浮动页码气泡，松手后跳转。
· 显隐规则见 4.3。

5.6 目录抽屉

· 左侧滑出，宽 320px，--z-drawer。
· 树形结构，当前章节高亮 --c-bg-selected + 文字 --c-accent-text（不得用 --c-accent，亮色对比度不足）。
· 章节数 > 200 时虚拟滚动。
· 搜索目录：抽屉顶部输入框，过滤即时。

5.7 空状态

· 结构（v1.12 修订）：--icon-xl（48px，--c-text-tertiary）→ 标题 --fs-20 → 主按钮。
  **没有说明句**。标题回答「现在是什么」，按钮回答「下一步做什么」，
  中间那句「试试其他关键词。」「切换到"全部"查看。」只是把按钮的话复述一遍。
  早期版本靠这几句撑场面，那是布局没排好时的补丁，不是必要信息。
· 书架为空文案：标题「书架还是空的」+ 按钮「导入文件」/「导入文件夹」。
· 搜索无结果：标题「没有找到匹配的书」+ 按钮「清空搜索」。
· 筛选无结果：标题「这个分类还没有书」+ 按钮「查看全部」。
· 书架插画保留：它承担「这里该放书」的引导，是插画不是文案。

5.8 Toast / 对话框

· Toast：底部居中，最多 3 条堆叠，3 秒自动消失，--z-toast。可撤销操作在 Toast 内提供「撤销」（5 秒内有效，与自动消失时间对齐，见下）。
  · 含「撤销」按钮的 Toast 驻留 5 秒，普通 Toast 3 秒。
· 危险操作必须用对话框二次确认，主按钮为 Danger 类型。
· 确认清单（v1.3 明确边界）：
  · 必须对话框：「删除本地文件」「从书架移除全部」「重建书库」。
  · 必须 Toast 撤销，不得用对话框：「清空阅读进度」「从书架移除」单本。可撤销的低代价操作不阻塞。
· 对话框宽 400–480px，--r-lg，--shadow-dialog，遮罩 --c-overlay。

5.9 补充组件

Tooltip：延迟 400ms 显示，背景 --c-bg-elevated，--fs-12，--r-sm，--shadow-popover，最大宽 280px。

Skeleton：背景 --c-bg-hover，圆角 --r-sm，1200ms 循环透明度脉冲（0.6 → 1 → 0.6），prefers-reduced-motion 下静止。

SegmentedControl（视图切换）：高 32px；选中项背景 --c-bg-selected 或 --c-bg-elevated，不使用 --shadow-popover；未选中透明；通过背景与文字颜色区分状态。--fs-13。

右键菜单：背景 --c-bg-elevated，--r-md，--shadow-popover，行高 32px，图标 --icon-sm，危险项文字 --c-danger。

5.10 图标规范

· 统一使用 Lucide 图标库，默认 2px 描边，不使用填充风格混搭。
· 功能图标禁止使用 Emoji；空状态插画可使用彩色，但不作为功能图标。
· 尺寸严格使用 --icon-sm / --icon-md / --icon-lg / --icon-xl 四档。
· 状态变化通过颜色、透明度、背景表达，不改变线宽。
· 同一组图标（如顶栏、底栏）必须保持同一描边风格和视觉重量。

6.4 漫画视觉规范

· 图片保持原始比例，不裁剪、不拉伸；object-fit: contain。
· 单页模式：图片居中，四周留白最小 --sp-6。
· 条漫模式：图片宽度 = min(窗口宽, 800px)，垂直连续，图片间距 --sp-2；滚动行为见 6.2。
· 高清图片：按可视区域 DPR 解码，不加载原图全尺寸；预加载前后各 3 页的缩略尺寸，翻页后解码全尺寸。
· 宽屏双页规则见 6.3，本节不重复定义阈值。

6.5 PDF 视觉与模式规范

· 页面间距 --sp-6（24px），背景 --c-bg-reader，页面本身不加阴影。
· 连续滚动时用间距区分页面，不用分割线。
· 横向 PDF：适合宽度优先，自动旋转按钮出现在底栏缩放控件左侧。
· 页面旋转按钮：底栏 ↻ 图标，每次 90°，仅 PDF 显示；旋转后保持当前页。
· 渲染失败：显示占位卡片（页面尺寸 + 居中错误图标 + “重新渲染”按钮），不显示空白。

PDF 模式切换（v1.3 与 UX 规范 §7.3 统一，带防抖）：

· 默认：单页翻页模式（点击左右 25% 翻页）。
· 自动切换阈值：缩放 > 110% 切连续滚动；缩放 < 95% 切回翻页。100% 附近留 10/5 个百分点缓冲，避免在 100% 上下抖动时反复跳变。
· 工具栏提供模式锁定按钮，用户可手动锁定“翻页”或“连续滚动”。锁定后自动切换完全停止，直到用户解除锁定。
· 手动选择优先于自动切换。
· 模式切换保持当前页与阅读位置；连续滚动切回翻页时，定位到当前可视区域顶部页。

v1.3 修正：v1.2 写「>100% 切连续 / 回 100% 切回」，与 UX 规范 v1.1 的 110%/95% 防抖直接冲突；现以带缓冲的 110%/95% 为准。

8. 可访问性

· 正文与背景对比度 ≥ 7:1（WCAG AAA，阅读场景），UI 文本 ≥ 4.5:1。四种阅读主题实测 10.6–13.5:1。
· --c-text-tertiary 仅用于占位符/弱提示，暗色 5.7:1、亮色 4.9:1；禁用文本豁免但不得承载信息。
· 输入框边框 --c-border-strong 满足 3:1：暗色 #737A84 对 surface 3.54:1、对 app 4.06:1、对 elevated 3.19:1；亮色 #888E97 对 #FFFFFF 3.30:1、对 #F7F7F5 3.08:1。
· 强调色按钮文字使用 --c-text-on-accent：暗色 #0B1220 对 #5B8DEF 5.8:1，亮色 #FFFFFF 对 #2F6FEB 4.57:1，均 ≥4.5:1。
· 文字型强调色使用 --c-accent-text：暗色 5.2:1、亮色 4.9:1；不得用 --c-accent 直接写文字（亮色 4.26:1 不达标）。
· 所有图标按钮有 aria-label；所有可交互元素可 Tab 到达。
· 焦点环统一 --c-border-focus，不可移除。
· 支持系统字体缩放：UI 使用 rem，根字号 16px。
· 动效遵循 prefers-reduced-motion。
· 漫画/PDF 提供页码与进度文本，供屏幕阅读器播报。
· 键盘用户必须能唤出自动隐藏工具栏（F6 / Tab）。

9. 性能相关 UI 约定

· 书架首屏先渲染骨架卡片，封面异步加载，完成淡入 120ms。
· 封面缩略图统一生成 320px 宽缓存，书架不直接加载原图。
· 列表/网格超过 200 项时启用虚拟滚动（经验阈值，调整需登记）。
· 阅读区禁止常驻 box-shadow、filter 做装饰；工具栏 overlay 的 backdrop-filter 属于例外。
· 所有图片 loading="lazy" + 显式宽高，避免布局抖动。
· PDF/漫画按可视区域渲染，离屏 canvas 及时销毁。

10. 文件管理与异常反馈

10.1 两种移除操作必须区分

操作 行为 确认文案
从书架移除 仅删除数据库记录与缓存，保留原始文件 「从书架移除？原始文件不会被删除。」（Toast + 撤销，非对话框）
删除本地文件 删除原始文件 + 数据库记录 + 缓存 「删除本地文件？此操作不可恢复。」（Danger 按钮，对话框）

右键菜单分组：菜单顺序见 5.4；「从书架移除」与「删除本地文件」之间必须有分隔线，不得无分隔相邻。

删除安全机制：

· 删除前对话框显示完整文件名和所在路径。
· 支持系统回收站时优先移入回收站，不直接永久删除。
· 执行顺序：移文件 → 删记录 → 删缓存。
· 先移动文件成功，再删除数据库记录；文件移动失败则保留书架记录并 Toast 错误。
· 文件移动成功但删记录失败：尝试从回收站恢复文件；恢复成功则书架不变；恢复失败则保留记录并置为「待恢复」（见 5.4 卡片异常态），右键提供「重新定位」「移除记录」。
· 删记录成功但清缓存失败：不影响正确性，后台清理，不提示。
· 默认操作是「从书架移除」，避免误删。

v1.3 修正两处与 UX 规范的接缝：
① 文件损坏——v1.2 与 UX 的「进入阅读页显示错误态」冲突，现统一为「打开时对话框，不进入阅读页」，因为损坏文件无法定位进度，进阅读页只会得到空壳。
② 进度恢复失败——v1.2 写「静默回退到开头 / 已从头开始」，与 UX 的「回退到最近有效位置 / 已回到最近的可用位置」冲突，现统一为后者：能回到最近的可用位置就不该把用户扔回开头。

10.3 导入进度

· 批量导入显示顶栏下方进度条（高 2px，--c-accent），不阻塞 UI。
· 单文件导入用 Toast 即可。

11. 实现约定

文件结构

```
src/
  styles/
    tokens.css        # 全部 CSS 变量
    themes.css        # data-theme / data-reader-theme 映射
    global.css        # reset + 基础排版
  components/
    ui/               # Button, Input, Dialog, Toast, Tooltip, Skeleton...
    shelf/            # BookCard, ShelfGrid, ShelfList, Sidebar
    reader/           # ReaderShell, TopBar, BottomBar, TOCDrawer
```

规则

1. 组件样式优先 CSS Modules 或 Tailwind；若用 Tailwind，token 映射到 theme.extend.colors，禁止 bg-[#1B1D21] 任意值。
2. 组件不得自行定义颜色/字号/间距常量，一律引用 token。
3. 新增 token 必须先改本文件，再改 tokens.css。
4. 图标统一 Lucide，尺寸 16 / 20 / 24 / 48 四档，2px 描边。
5. 中文文案统一使用中文标点；省略号用 …。
6. 动画只用 transform 和 opacity。
7. 组件复用优先：同一视觉元素在书架、小说、漫画、PDF 中出现时，必须复用同一组件。
8. 字号 token 以 px 定义、构建转 rem；组件中禁止随意混用 px / rem 定义字号。
9. 文字型强调色一律 --c-accent-text，禁止 --c-accent 直写。

禁止事项

· 禁止阅读正文区纯白 #FFFFFF + 纯黑 #000000。
· 禁止用整页 loading 转圈替代骨架屏（按钮级 spinner 允许）。
· 禁止模态框嵌套超过一层。
· 禁止工具栏超过 1 个 Primary 按钮（Danger 不计入）。
· 禁止只有视觉效果、没有实际功能的控件。
· 禁止擅自删除、弱化或替换已有交互功能。
· 禁止功能图标使用 Emoji。
· 禁止在 P1 出现 P2 功能入口（含置灰、含侧栏标签、含顶栏书签）。
· 禁止用 --c-accent 直接写文字，必须用 --c-accent-text。

12. AI 设计执行约束

本章对 AI 编程工具具有最高约束力。

1. 本规范是 UI 实现的最高视觉约束，不得自行创造与规范冲突的设计。
2. 优先复用现有组件、Design Token 和布局结构，禁止无必要重复创建组件。
3. 新增 UI 元素必须遵循现有色彩、字体、间距、圆角和动效体系。
4. 需求与规范冲突时，优先保持设计系统一致性，并明确指出冲突点。
5. 不得为视觉丰富添加没有实际功能的装饰元素。
6. 所有交互控件必须具备完整状态反馈（5.1），不允许只有视觉效果没有功能的控件。
7. 不得擅自删除、弱化或替换已有交互功能。
8. 修改组件时，检查其在书架、小说、漫画、PDF 四个场景中的一致性。
9. 完成页面后，检查暗色、亮色、Sepia、OLED四种主题。
10. UI 实现必须同时满足视觉、交互、可访问性；冲突时可访问性优先。
11. 规范未覆盖的场景，先在本文件登记补充，再实现，不得静默发挥。
12. 交付前必须逐项通过第 13 章验收清单。
13. 引用色值时以本文件表格为准，不得沿用 v1.2 及更早版本的历史值。
